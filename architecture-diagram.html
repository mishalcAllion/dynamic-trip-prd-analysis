3 API Layer -- 6 Endpoints with Request Flow
Read Endpoints
GET /trips
Returns trip list for authenticated member
Returns: Trip[] (summary)
Auth: Member token -> Notion member mapping
Notion queries: Trips DB + Members DB
GET /trips/:id
Trip metadata + all components (summary) + comment counts + insider tips (HTML)
Returns: Trip + Component[] + InsiderTips
Cache: Tips 30min, components 5min
Notion queries: Trips DB + Components DB
GET /trips/:id/components/:componentId
Full component detail -- images, reasoning, pricing, comments
Returns: Component (full)
Performance: Lazy load on card tap, prefetch on scroll
Notion queries: Components DB
Write Endpoints
PATCH /trips/:id/components/:componentId/decision
Update Client Decision + Decision Date + Decided By
Side effect: Auto-creates Notion Task Dashboard task
Dedup: Same component within 5 min = single task
Notion writes: Components DB + Task Dashboard
POST /trips/:id/components/:componentId/comments
Write to Client Request text field
Side effect: Auto-creates Notion Task Dashboard task
Notion writes: Components DB + Task Dashboard
PATCH /trips/:id/feedback
Submit planning or trip feedback (stars + tags)
Side effect: Auto-creates task (Urgent if rating <= 2)
Notion writes: Trips DB + Task Dashboard

4 Mobile Screens -- S1 through S6 Data Architecture
S1
Trip Page
API: GET /trips/:id
Data: Trip meta, all components (summary), insider tips
State: Zustand trip store
Phase: Visibility controlled by trip status
Notes: Main entry point. Renders day-by-day itinerary, status banner, and all section containers.
S2
Component Detail View
API: GET /trips/:id/components/:cId
Data: Full component (images, reasoning, pricing, comments)
State: Zustand component detail store
Load: Lazy loaded on card tap
Notes: Carousel images, advisor reasoning, pricing display, decision buttons.
S3
Comment Sheet
API: POST /comments (write), GET component (read)
Data: Client Request text, Ops Response text
State: Local form state
Side effect: Creates Notion Task
Notes: Two text fields only (not JSON array). Bottom sheet modal.
S4
Decision Confirm
API: PATCH /decision
Data: Client Decision, reason tags
State: Optimistic UI update
Side effect: Creates Notion Task
Notes: Thumbs up/down (not binary). 5 min dedup on task creation.
S5
Day Picker
API: None (local)
Data: Date range from S1 trip data
State: Local selection state
Interaction: Scrolls S1 to selected day
Notes: Pure UI component. No server calls. Reads trip date boundaries from S1 store.
S6
At a Glance
API: GET /trips/:id (same as S1)
Data: Trip timeline, component status badges
State: Same trip store as S1
View: Compact horizontal timeline view
Notes: Shared store with S1. No additional API calls required.
Screen Dependencies
S1 S2 (detail), S3 (comment), S4 (decision), S5 (day pick), S6 (glance)
S2 S3 (comment from detail), S4 (decision from detail)
